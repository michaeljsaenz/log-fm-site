## The Outcome

`local-cluster` is a CAPD Kubernetes cluster with:

- **Nodes** - one control plane and two workers, Docker containers from the
  `quick-start` ClusterClass
- **Infrastructure** - Cilium (CNI), cert-manager (TLS), and ingress-nginx
  (ingress)
- **Fleet** - one `fleet-agent`, registered into the management Fleet

> The manifest comes from the host git daemon (`:9418`) and the charts from the
> chart server (`:8879`), so the provision stays offline.

## Architecture

Fleet applies the manifest, then the controllers reconcile in order:

![Workload provisioning on one host: capi-mgmt delivers the local-cluster manifest via Fleet, CAPI and CAPD build the container nodes, CAAPH pushes Cilium, cert-manager, and ingress-nginx from the host chart server, and CAAPF imports the cluster into Fleet with a single fleet-agent](/images/hydrating-architecture.png)

1. **Fleet** clones the committed cluster manifest from the git daemon
   (`:9418`) and applies the CAPI `Cluster` to `capi-mgmt`.
2. **CAPI + CAPD** reconcile the `quick-start` topology into Docker containers:
   one control plane and two workers.
3. **CAAPH** matches the cluster's labels and pulls those charts from the chart
   server (`:8879`).
4. **CAAPH** renders a `HelmReleaseProxy` per match that `helm install`s Cilium,
   cert-manager, and ingress-nginx into the workload cluster (push).
5. **CAAPF** sees the new `Cluster` and its kubeconfig Secret, imports it into
   Fleet, and installs exactly one `fleet-agent`.

> **Labels are the contract.** `cni=cilium`, `tls=cert-manager`, and
> `ingress=nginx` select which HelmChartProxies apply.

## Prerequisites
- [capi-local-lab](https://github.com/michaeljsaenz/capi-local-lab) cloned locally (featuring the `p1/` scripts and manifests).
- A running management plane cluster (`make bootstrap`; see [Bootstrapping an Ephemeral Local CAPI Management Plane]({{< ref "/posts/2026.001.md" >}}).

## Run & Verify

### Run

```bash
make provision
```

Requires `make bootstrap` first (see [Bootstrapping an Ephemeral Local CAPI Management Plane]({{< ref "/posts/2026.001.md" >}})). In order it:

- preflights the management plane and chart server
- confirms the workload-cluster manifest is committed in the local Git repo
- applies the `quick-start` ClusterClass and HelmChartProxy definitions (injecting chart-server IP)
- labels the Fleet local cluster to match the GitRepo target
- applies the cluster GitRepo and Fleet applies the manifest
- CAPI and CAPD provision the control plane and workers

### Verify

```bash
make verify CLUSTER=local-cluster
```

Or check the cascade directly:

```bash
# Cluster is Provisioned and Available
kubectl get cluster local-cluster -n default
# -> local-cluster   quick-start   True   ...   Provisioned   (AVAILABLE=True)

# One control plane + two workers, all Running
kubectl get machines -n default
# -> local-cluster-...   Running   (x3: 1 control-plane, 2 workers)

# Infra deployed by CAAPH (one HelmReleaseProxy per addon)
kubectl get helmreleaseproxy -A
# -> cilium-local-cluster-...         True   deployed
# -> cert-manager-local-cluster-...   True   deployed
# -> ingress-nginx-local-cluster-...  True   deployed

# Cluster imported into Fleet by CAAPF, heartbeating
kubectl get cluster.fleet.cattle.io local-cluster -n default
# -> local-cluster   1/1   <recent LAST-SEEN>
```

## Key Insights

- **Labels are the API.** Cluster labels select infrastructure now (CAAPH) and
  apps later (Fleet). Provisioning a differently shaped cluster is a label edit.
- **Order the cascade, don't race it.** Cilium lands first so nodes go Ready -
  without a CNI every other addon's pods sit `Pending`; cert-manager and ingress
  follow once there's a network.
- **Push for infra, pull for apps.** CAAPH helm-installs infrastructure from the
  management cluster; CAAPF installs the one fleet-agent that later app delivery
  pulls through. Same cluster, two mechanisms.
- **Commit, not working tree.** Fleet serves committed refs; `make provision`
  guards it so an uncommitted change fails fast instead of producing an empty
  bundle.
- **Self-contained on top of the engine.** One idempotent `make provision`
  mirrors `make bootstrap`; `make deprovision` removes the cluster and addons and
  leaves the engine intact.
