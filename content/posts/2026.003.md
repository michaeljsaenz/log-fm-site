## The Outcome

The `hello-world` app runs on `local-cluster`, delivered from one committed
manifest by GitOps alone:

- **App** - a two-replica `nginx:alpine` Deployment and a ClusterIP Service
- **Delivery** - one Fleet `GitRepo` (`apps`) targeting clusters labeled
  `environment=local`
- **Mechanism** - the downstream `fleet-agent` pulls; the management plane never
  reaches into the workload cluster

> Bundle content comes from the host git daemon (`:9418`), so delivery stays
> offline.

## Architecture

CAAPF registered the cluster into Fleet during provisioning and copied its labels.
Delivery is then pure GitOps: the upstream `gitjob` clones the committed ref and
renders a `Bundle`, the `apps` GitRepo scopes a `BundleDeployment` to clusters
labeled `environment=local`, and the cluster's own `fleet-agent` pulls it back
down.

![Zero-touch app delivery on one host: the apps GitRepo in capi-mgmt renders a hello-world Bundle, Fleet scopes a BundleDeployment to local-cluster by environment=local, and the downstream fleet-agent pulls it from the management cluster](/images/onboarding-architecture.png)

> - **Pull, not push.** Infrastructure addons are pushed by CAAPH
>   (`helm install`); apps are pulled by the `fleet-agent`, so no workload
>   credentials flow upstream.
> - **Label-scoped.** The CAPI `Cluster` carries `environment=local`; CAAPF copies
>   that label onto the Fleet `Cluster` it registers, and the `apps` GitRepo's
>   `clusterSelector` matches on it. A cluster receives the app by wearing the
>   label, not by being named in the GitRepo.

## Nuance

Delivery is zero-touch, but two placement rules make it work:

- **Namespace must match the cluster.** A `GitRepo` only targets clusters in its
  own namespace. CAAPF registers the cluster in `default` (with the CAPI
  `Cluster`), so the `apps` GitRepo lives there too - not `fleet-local` (Fleet's
  namespace for the management cluster itself).
- **Committed refs only.** Fleet clones a committed ref, not your working tree;
  `make onboard` refuses to apply until the manifests are committed.

Scaling is just more commits and labels: a second app is another path in the
`GitRepo`; labeling another cluster `environment=local` delivers the app there
too.

## Run & Verify

### Run

```bash
make onboard
```

Requires `make provision` first (see [Provisioning a CAPI Workload Cluster with Fleet]({{< ref "/posts/2026.002.md" >}})). In order it:

- preflights tooling and the management context
- requires a cluster labeled `environment=local` (registered by CAAPF during
  provisioning)
- applies the `apps` GitRepo once the manifests are committed

Fleet then clones the ref and the `fleet-agent` pulls the bundle.

### Verify

Check the delivery directly:

```bash
# The apps GitRepo is delivered (bundle deployments ready on the mgmt cluster)
kubectl get gitrepo apps -n default
# -> apps   git://host.docker.internal/capi-local-lab   <sha>   1/1

# The hello-world bundle is deployed to the registered cluster
# (the bundle name is derived from the GitRepo name plus the committed path)
kubectl get bundles -n default
# -> apps-<path>-hello-world     1/1
# -> fleet-agent-local-cluster   1/1

# On the workload cluster, the app is Running
# (kubeconfig written by `make verify CLUSTER=local-cluster`)
KUBECONFIG=/tmp/local-cluster-kubeconfig kubectl get deploy,svc -l app=hello-world
# -> deployment.apps/hello-world   2/2   ...
# -> service/hello-world           ClusterIP ...
```

## Key Insights

- **Pull for apps, push for infra.** Addons are `helm install`ed by CAAPH; apps
  are pulled by the `fleet-agent` - no upstream access to the workload.
- **Membership is a label.** Onboarding a cluster is one `environment=local`
  label, not a new pipeline.
- **Namespace must match.** The `GitRepo` and the registered cluster share a
  namespace (`default`), or the target never matches.
- **Commit, not working tree.** Fleet serves committed refs; `make onboard` fails
  fast on uncommitted changes.
- **Self-contained.** `make onboard` mirrors `make bootstrap` and
  `make provision`; `make offboard` removes the app and leaves the cluster intact.
